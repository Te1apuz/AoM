# Шаг 2: подбор героя под артефакт

Дата: 2026-10-25. Статус: черновик на согласовании.

## Зачем

Бот для игроков Age of Magic. Шаг 1 (идёт сейчас): игрок присылает скриншот
инвентаря, бот распознаёт 4 буквы созвездий выбранного артефакта (A–L).
Шаг 2 (этот документ): по этим буквам бот советует, кому отдать артефакт.
Шаг 3 (потом): бот сам читает характеристики артефакта со скриншота.

Сейчас игроки подбирают героя вручную по таблице RedCat «Артефакты AoM»:
вбивают буквы, сортируют по совпадениям, дальше сами смотрят навыки. Бот
делает то же самое за них и сразу сужает выбор до нескольких имён.

## Что видит игрок

1. Бот распознал буквы артефакта (шаг 1) и показывает их.
2. Под ними кнопки типа артефакта:
   **Массовая · Одиночная · Мульти · Контратака · Вспомогательная**.
   Игрок нажимает ту, под которую артефакт (по его главному свойству).
3. Бот отвечает текстом из двух блоков.

**Блок 1. По созвездиям: можно надевать как есть.**
Три группы по числу совпавших букв: 4/4, 3/4, 2/4. В каждой до 3 героев,
лучших по выбранному типу. Под каждой непустой группой кнопка
«Показать всех (N)».

**Блок 2. Под перековку.** 4–5 героев, у которых выбранный тип выражен
сильнее всего, без учёта букв. Перековка меняет только буквы созвездий
(подтвердил пользователь), поэтому для этих героев артефакт нужно перековать
под их буквы. Буквы героя показываются рядом с именем.

Картинки героев появятся позже; на шаге 2 ответ только текстом.

Пример на живых данных (артефакт L G E B, кнопка «Массовая»; случайные
места при равенстве могут отличаться):

```
Артефакт: L G E B · тип: Массовая

По созвездиям
4/4 — Древерад (B G E L)
3/4 — Теон (B E D G), Тан'Арг (B G L L), Стар'вальд (G B E A)   [Показать всех (7)]
2/4 — Артус (G F E A), Люциус (E E B A), Врея (D B B E)          [Показать всех (50)]

Под перековку
Герда (B B B B), Рок (B J B B), Нимуэ (B B B B), Ройнар (B B J J), Гротто (B B B B)
```

## Правила

### Совпадение

Совпадение = пересечение мультимножеств: сколько из 4 букв артефакта
есть у героя с учётом повторов (артефакт `B B E L` и герой `B E E G` дают 2).
Проверено: для артефакта L G E B, вбитого в живую таблицу, подсчёт совпал
с колонкой «совпадения» RedCat у всех 209 героев.

Группы 4/4 и 3/4 обычно маленькие (на 6 проверенных артефактах: 4/4 — 0–1
герой, 3/4 — 1–7), 2/4 — 30–50. Пустая группа выводится строкой «—».

### Оценка героя по типу

| Кнопка | Оценка героя |
|--------|--------------|
| Массовая | число массовых (зелёных) навыков из 4 |
| Мульти | число навыков с текстом «Мульти» |
| Одиночная | 0, если есть хоть один массовый навык; иначе число одиночных (оранжевых) навыков |
| Контратака | 2 — своя контратака, 1 — только «за счёт другого», 0 — нет |
| Вспомогательная | 2 — своя вспомогательная, 1 — только «за счёт другого», 0 — нет |

Сортировка: по оценке по убыванию, при равенстве случайно (заново при каждом
запросе), чтобы не выигрывали всегда герои из начала таблицы.

Блок 1: внутри каждой группы показываются 3 первых после сортировки.
Блок 2: кандидаты — все герои, кроме уже показанных в блоке 1; 5 первых.

## Данные

Источник — живая Google-таблица RedCat (в `infrastructure.md` она записана как
главный источник), выгрузка без авторизации:
`https://docs.google.com/spreadsheets/d/18IWMCIs8q2usE4HzB9enjbVJ6C1YLw50/export?format=xlsx`.
`AoM Артефакты!!!.xlsx` в репо устарел (197 героев против 209) и не годится.

Лист «Таблица», герои с 6-й строки, колонки:

| Колонка | Что | Как читать |
|---------|-----|-----------|
| B | фракция | текст |
| C | имя героя | текст; пустое — не герой |
| F, H, J, L | 4 буквы созвездий | текст A–L |
| M | совпадения с артефактом из строки 3 | не нужна боту, только для проверки |
| N, O, P, Q | навыки 1–4 | **цвет заливки**: `FF00FF00` массовая, `FFFF9900` одиночная (легенда в N3:P4); текст «Мульти» в ячейке — мульти-удар |
| R | своя контратака | непустой текст или заливка `FFFF0000` |
| S | контратака за счёт другого героя | непустой текст или заливка |
| T | своя вспомогательная атака | непустой текст или заливка `FF9900FF` |
| U | вспомогательная за счёт другого | непустой текст или заливка |

Ограничение: тип навыка хранится **только цветом заливки**. CSV-выгрузка и
Sheets values API цвет теряют, поэтому импорт читает `.xlsx` вместе со
стилями (`xl/styles.xml` → `cellXfs` → `fills`). Красный и фиолетовый в
колонках навыков практически не встречаются: контратаки и вспомогательные
атаки RedCat ведёт в колонках R–U.

Срез живой таблицы на 2026-10-25: 209 героев, у всех по 4 буквы; массовый
навык есть у 102, «Мульти» у 66, своя контратака у 26, чужая у 54, своя
вспомогательная у 12, чужая у 74.

## Цели

- По распознанным буквам и одной кнопке дать короткий понятный ответ: кого
  надеть сразу и под кого стоит перековать.
- Использовать только то, что уже есть в таблице RedCat.
- Логика подбора не зависит от Telegram и от распознавания: на вход буквы и
  тип, на выход два блока. На шаге 3 кнопку заменит прочитанная
  характеристика, а подбор останется тем же.

## Не цели (на шаге 2)

- Чтение характеристик артефакта со скриншота (шаг 3).
- Картинки героев в ответе (следующий этап после текста).
- Учёт того, какие герои есть у игрока, и сила или редкость героя: в таблице
  этих данных нет.
- Добавление и правка героев через бота (отдельная задача про роли и PR).

## Анти-цели

- Ответ-простыня из 50 имён: по умолчанию игрок видит не больше 3 на группу
  и 5 под перековку.
- Тихо устаревшие данные: если таблица не загрузилась, бот говорит об этом,
  а не отвечает по старому снимку без предупреждения.
- Выдумывание того, чего нет в таблице (тиры, «лучший герой игры»).

## Решения пользователя

- Ответ из двух блоков: 2–3 героя на группу 4/3/2 и отдельно 4–5 героев под
  перековку.
- Перековка меняет только буквы созвездий.
- Тип артефакта на шаге 2 игрок выбирает кнопкой; автоматическое чтение
  характеристик — шаг 3.
- Опираться только на данные таблицы.
- Оценка по типам и случайный выбор при равенстве — как в таблице выше.
- Сначала текст, картинки потом.

## Решения, принятые мной (проверить)

- Кнопка «Одиночная» отбирает только героев без массовых навыков, иначе она
  ничего не отсеивает (одиночный навык есть почти у всех).
- Условные записи («пассивка с пробудкой», «если меньше 35% хп») считаются как
  полноценные свои. «2-й навык Артуса» / «3-й навык Дэнайи», которые дают
  контратаку всем, не учитываются: иначе контратака была бы у каждого.
- В блоке 1 показываются и герои с оценкой 0, если лучше в группе никого нет:
  группа про буквы, тип только упорядочивает.
- Блок 2 берёт кандидатов из всех героев, кроме показанных в блоке 1, а не
  только из 0/4–1/4: герой из 2/4 с высокой оценкой — хороший кандидат на
  перековку.
- Документ лежит в форке `Te1apuz/AoM`, в `docs/superpowers/specs/`, в своей
  ветке.

## На усмотрение исполнителя

- Язык, библиотека Telegram, структура модулей. Шаг 1 сейчас — спайк на
  Python со stdlib long polling (`collector_bot.py`); строить на том же стеке
  разумно, но это не требование.
- Как часто перезагружать таблицу (кэш; разумно — раз в несколько часов плюс
  команда принудительного обновления у админа).
- Точное оформление текста, эмодзи, разметка Telegram.
- Как кнопки «Показать всех (N)» выводят длинный список (одно сообщение,
  постранично).
- Тесты: подбор — чистая функция, её стоит покрыть тестами на фиксированном
  снимке таблицы, включая проверку совпадений против колонки M.
